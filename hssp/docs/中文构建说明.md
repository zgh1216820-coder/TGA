# HSSP当时是怎样构建的

HSSP不是重新采集图像，而是把11个公共来源整理成适合异构联邦持续学习的任务流。最关键的旧代码叫 `prepare_vqa_rad.py`，名字容易误导：它并不只处理VQA-RAD，而是处理全部11个来源。电脑与服务器的这个文件哈希完全相同。

先把不同来源的Parquet、CSV、JSON、ZIP、TAR解析成统一格式：图像转换为RGB JPEG，文字整理为包含图像标记的问题和一条回答。选择题把选项写入提示，并把答案转成选项字母。InspecSafe的问答由图像标注中的组件或异常标签构造，不是直接照搬现成的问答数据。

然后按答案分布切训练子集：取最常见的20类答案及其余类，以alpha=0.5的Dirichlet分布制造非独立同分布，每个子集最多4000条，不重复抽取；过小的子集从较大的子集移入样本，最终配置的最小值为500。测试子集每来源最多1000条，并可在同一来源的多个任务单元间共享。ChemVQA和MMAD先打乱并按80/20拆分，其他来源主要沿用原始train/test/val文件。

最后由场景JSON明确指定10个客户端，每个客户端4个有序任务；6个客户端使用1B、4个使用3B。总共40个任务单元，包括31个开放式任务和9个选择题任务。难度标签也是预先写入的协议标签，不是模型根据结果自动推断的。

本次重新核验了服务器实际使用的80个训练/测试JSON：全部与2026年8月15日的哈希记录相同。训练151744条；测试调度使用39240次，对应10240条唯一测试记录。引用的图像均存在。本项目只保存编号、顺序、相对图像路径与内容哈希，不保存原始图像和问答正文。

需要区分三个层次：

1. **验证原实验用的是什么数据：已完成。**文件哈希及19万余条记录的成员顺序已冻结。
2. **从原标准化候选记录恢复当时的划分：提供工具并核验。**按内容哈希选取并恢复原顺序，不重新随机切分。
3. **从当前Hugging Face下载开始一键重现原划分：目前不能这样承诺。**历史下载版本未找到，原脚本也没有固定随机种子；重新设置seed=1并不等于恢复历史随机状态。

因此这个项目可以作为论文的协议、代码和冻结划分佐证；它不能自动证明所有基线都采用了相同训练预算。后者需要逐项运行记录，见FAIRNESS.md。
